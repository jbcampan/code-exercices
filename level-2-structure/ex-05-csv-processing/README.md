# Ex-2.5 — Read and Write CSV Cleanly

**Level:** 2
**Estimated time:** 1h
**Track:** Python → file-processing

---

## Goal

Parse an EC2 instance inventory from a CSV file, filter running instances, compute their monthly cost, and export the result to a new CSV file. Mirrors a real-world task: exporting IAM audit reports, EC2 inventories, or CloudWatch metrics as clean CSVs to share with non-technical teams.

---

## Concepts covered

- `csv.DictReader` — each row becomes a dict keyed by column headers
- `csv.DictWriter` with explicit `fieldnames` and `extrasaction="ignore"`
- `writeheader()` to write the header row
- `newline=""` and `encoding="utf-8"` in `open()` for cross-platform safety
- Why `split(",")` breaks on real CSV files (quoted fields containing commas)
- `collections.defaultdict` for aggregation
- `round()` to avoid floating-point noise

## Instructions

**Input file format** — `data/instances.csv`:
```
instance_id,instance_type,state,region,cost_per_hour
i-0a1b2c3d4e5f6a7b8,t3.micro,running,eu-west-1,0.0116
...
```

One row per EC2 instance. The `state` field can be `running`, `stopped`, or `terminated`. Some fields may contain commas inside quotes — the `csv` module handles this transparently.

**Steps the script must perform:**

1. Load `data/instances.csv` into a list of dicts with `DictReader`.
2. Filter to keep only `running` instances.
3. Add a `monthly_cost` field: `cost_per_hour * 720`, rounded to 2 decimal places.
4. Export the result to `data/filtered.csv` using `DictWriter` with explicit `fieldnames`.
5. Print a summary of total monthly cost per region, sorted descending.

## Constraints

- Always open CSV files with `newline=""` and `encoding="utf-8"`.
- Use `DictWriter` with an explicit `fieldnames` list — no surprise columns.
- Transformation functions receive a list and return a list — no file I/O inside them.
- No `split(",")` anywhere.
- File paths defined as module-level constants, never hardcoded inside functions.

## Key takeaways

1. **`DictReader` eliminates index fragility** — `row["region"]` is always correct even if column order changes; `row[3]` is not.
2. **`split(",")` is not a CSV parser** — a field like `"stopped, pending restart"` contains a comma; `split` produces three tokens, `DictReader` produces one.
3. **`newline=""` is not optional** — on Windows, Python's universal newline mode would insert blank rows between every data row; this one-liner prevents hours of debugging.
